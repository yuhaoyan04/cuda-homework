# 几何知识速览（学生版，不包含 CUDA 解答）

本课程面向已经掌握 CUDA 基础、但未必学习过计算几何的学生。以下只给出数学问题及实现注意事项，具体 GPU Kernel、算法和优化由学生自行设计。

## 1. 采样点与目标

规则网格节点 `p(i,j,k) = origin + dx*(i,j,k)`，输出索引 `i + nx*(j + ny*k)`。
对于封闭、朝向一致的三角网格表面 `M`，有符号距离为

\[
\phi(p)=\begin{cases}
-d(p,M), &p\text{ 在物体内部},\\
+d(p,M), &p\text{ 在物体外部},
\end{cases}
\quad d(p,M)=\min_{t\in M}\min_{q\in t}\|p-q\|_2.
\]

物体表面处距离为零，实际浮点计算应考虑接近零时的符号不稳定。

## 2. 为什么不能只计算到顶点的距离

三角形上的最近点可能落在三角形的面内部、边内部或顶点处。如果只看三个顶点，会高估距离。

点投影到三角形的平面后，若投影的重心坐标 `(u,v,w)` 均非负且和为 1，则最近点为该投影；否则可比较该点到三条线段的距离。边退化为点的情况应特殊处理。计算只需向量点积、叉积、加减乘除与平方根。

## 3. 内外符号（射线奇偶法）

从待查询点向固定方向发出射线，通常奇数个表面穿越表示内部、偶数个表示外部。但是射线经过三角形顶点、共享边、共面三角形时，简单计数会出现重复或漏计。实现时必须制定一致的共享边/顶点计数规则，不能直接依赖一个不加处理的浮点等值判断。

教师提供的模型均应为封闭、无自交、朝向一致的三角网格；这并不自动消除浮点退化问题。学生可采用任何正确的符号判定方法，不强制使用射线奇偶法。

## 4. 最简单的 CUDA 并行思路（非要求采用）

一个自然的基线是每个 CUDA 线程负责一个网格节点，遍历所有三角形，计算最小无符号距离，再单独确定内外符号。这种方法易于理解与验证，但工作量随 `网格节点数 × 三角形数` 增长。可以作为后续优化的对照，而不必直接作为最终方案。

如果按三角形并行向网格写入，多个线程可能竞争更新同一个采样点；必须正确处理竞争与同步。仅使用 `atomicMin` 并不能直接解决浮点符号的可靠性问题。

## 5. 建议探索的 CUDA 优化方向

- 线程布局与连续访存；减小 warp 分歧。
- 顶点/三角形数据的 SoA/AoS 选择，以及只读缓存与共享内存分块。
- 粗筛包围盒、候选三角形、空间索引或 GPU 并行传播。
- 合理减少 Kernel launch、临时缓冲与全局访存。
- 使用 Nsight Systems / Nsight Compute 分析实际瓶颈；有工具可用时请提交数据。

至少两项优化需要有**相同测试数据、相同正确性阈值、相同计时边界**下的前后对比。仅增加代码复杂度不算优化证据。

## 6. 常见错误

- 把网格节点误认为体素中心（相差 `dx/2`）。
- 将 `i/j/k` 或顶点索引顺序弄反。
- 只写入部分 SDF，未初始化的格点残留旧结果。
- 只计算无符号距离、将外部全部写正数。
- 用浮点 `==0` 作为唯一零距离/退化判定。
- 在计时区间外完成实际 GPU 计算，或复用此前帧的输出。
- 用参考 CPU 结果的近似误差为自己的系统性错误辩解；需要独立核验。
